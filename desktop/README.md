# VOSR2 Lite 桌面壳（desktop/）

Tauri v2 桌面壳：Rust 侧只负责「窗口 / 托盘 / 通知 / 进程托管 / 更新」，业务全在 Python 后端
（`app/integrated_app`，FastAPI + Jinja2 + HTMX）。壳启动后拉起侧载 Python，等健康检查通过，
再把主窗口导航到 `http://127.0.0.1:<随机端口>/`。

```
desktop/
├─ src/                    壳自带的启动页（frontendDist，本地 tauri 源）
│  ├─ index.html           启动/报错/重试页（仅壳内可见）
│  └─ desktop-bridge.js    注入到后端页面的桥接（IPC、标题栏、更新弹窗、通知）
├─ src-tauri/
│  ├─ Cargo.toml           包名 vosr2lite-desktop，壳版本在此
│  ├─ tauri.conf.json      productName / identifier / 更新端点 / 更新公钥
│  ├─ build.rs             AppManifest::commands（必须与 main.rs 的 generate_handler! 一致）
│  ├─ capabilities/main.json   远程源（127.0.0.1:*）放行清单
│  ├─ permissions/autogenerated/*.toml   权限镜像（**必须入库**，见下文不变量）
│  ├─ icons/               应用图标（icon.ico / png / icns）
│  └─ src/                 main / python_process / health_check / port_manager / updater /
│                          tray / window / notification / drag_drop / config / crash_report
└─ tauri.key.pub           更新签名公钥（入库，作为 conf.pubkey 的校验基准）
```

## 开发运行

```bash
cd desktop
npm install                 # 仅装 @tauri-apps/cli（devDependency）
npm run dev                 # = tauri dev，会编译 Rust 并启动
```

开发态壳的目录解析顺序（`python_process.rs`）：

1. 可执行文件旁的 `app/start_portable.py`（打包态）
2. `CARGO_MANIFEST_DIR` 上溯两级（仓库根）的 `scripts/start_portable.py`（开发态）
3. Python 解释器：`<app_dir>/runtime/python.exe` → `<app_dir>/.venv/Scripts/python.exe` → 系统 `python`

因此本地调试需要先准备好 `.venv`（`install.bat` 或 `pip install -r requirements.txt`）。

## 打包（Windows / NSIS）

## 分发模型：瘦包 + 程序内下载

安装包**不含 torch 运行时、不含模型权重**。用户装完（几十 MB）后，由程序内的
「下载管理」页（`/downloads`，与首页/设置同级）按需安装：

- **运行环境**：torch/torchvision 的 cu128 wheels（约 2.5 GB），离线装进
  `app/bootstrap/` 自身的 site-packages——目录名不变，壳靠 `site-packages/torch`
  判定它已是完整运行时，无需第二份解释器。
- **模型权重**：走 HuggingFace / ModelScope（不占本项目托管带宽），复用
  `scripts/download_model.py` 的多源回退与断点续传。

首次启动时后端跑在**引导解释器** `app/bootstrap/` 上（只有 Web 依赖、无 torch）。
后端在缺 torch 时仍能完整启动——`app_server` 有路由级容错，单个路由模块导入失败
只打日志并跳过——所以下载页打得开，用户才能装上环境。壳的
`detect_python_mode()` 据此把入口切到 `/downloads` 而非首页。

```powershell
# 1) 构建壳（产物：src-tauri/target/release/VOSR2Lite.exe）
cd desktop && npm run build
#    注意：直接用 cargo build --release 得到的是 vosr2lite-desktop.exe（Cargo 包名），
#    tauri build 才会按 productName 重命名为 VOSR2Lite.exe；安装器脚本要求后者。

# 2) 瘦包（默认）：壳数据卷 + 增量包
#    自动下载 WinPython 3.12 → 只装 Web 依赖（不装 torch）→ 组装 app/bootstrap/
#    → 7z → SHA256SUMS / manifest.json / upload-list.txt
powershell -ExecutionPolicy Bypass -File scripts\build_desktop_bundle.ps1
#    环境包（torch cu128 wheels + 下载清单）：  -Mode runtime
#    两者都建（发版用）：                      -Mode all
#    已有准备好的便携解释器：                  -RuntimeDir D:\WPy64-312101 -SkipAutoPrepare -SkipDeps

# 3) 编译安装器（需 NSIS + 7-Zip）
cd scripts/installer
makensis /DAPP_VERSION=<应用版本> -DSRC_7ZA="C:\Program Files\7-Zip\7z.exe" setup.nsi
```

产物落在 `dist\desktop-release\`：

| 文件 | 说明 |
|---|---|
| `VOSR2Lite-Data.7z.001..NNN` | 瘦包数据卷（根为 `app/`，含 `bootstrap/`），与安装器同目录分发 |
| `VOSR2Lite-Runtime-cu128.zip.001..NNN` | 环境包：`-Mode runtime` 产出，供下载页获取 |
| `downloads_catalog.json` | 环境包清单（随应用分发，离线也能展示；换环境包须同步发新版应用） |
| `app-v<版本>.zip` + `.sha256` | 增量包（**zip 根即 `app/` 的内容**，不含 `app\` 外层包装） |
| `SHA256SUMS.txt` / `manifest.json` / `upload-list.txt` | 校验清单与元信息 |

三个易错点（脚本已固化，改动前先看 `build_desktop_bundle.ps1` 的注释）：

- **数据卷归档根必须是 `app/`**——安装器把它解到 `$INSTDIR`，随后校验 `$INSTDIR\app\start_portable.py`。
- **增量包归档根必须是 `app/` 的内容**——`updater.rs::extract_zip_with` 直接解到 `app.new/`，
  多包一层 `app\` 会换载出 `app\app\app\integrated_app`，壳找不到启动脚本。
- **`bootstrap` 目录名三处必须一致**——`python_process.rs::detect_python_mode`、
  后端 `_runtime_dir()`、打包脚本 `$BootstrapDirName`。改名要三处同步，否则壳认不出引导态。

实测（2026-10-30，Windows 11 / Rust 1.99.1）：壳 `17,209,344 B`（16.4 MiB）；安装器
`4,032,621 B`（3.85 MiB，把 17.9 MB 载荷压到 22.4%）；增量包 `app-v0.2.1.zip` 529.8 KB；
**瘦包数据卷 20.0 MB**（用最小解释器冒烟：载荷 66.8 MB / 2320 文件压到 20.0 MB，
单卷即可，无需分卷）。对比旧的全量数据卷：本机 `model/` 12 GB + torch 运行时约需 8 个 1900MB 分卷。

安装器只内嵌壳与 `version.json`，数据卷里放旧基线；这样「壳更新」不需要重打数 GB 数据卷。

最终一次发布 = `VOSR2Lite-Setup-v<版本>.exe`（约 4 MB）+ `VOSR2Lite-Data.7z.001..NNN`（数 GB）
+ `app-v<版本>.zip`（增量包，约 1 MB，走壳内更新）+ `SHA256SUMS`。

## 版本口径（四仓统一）

| 版本位 | 唯一定义处 | 规则 |
|---|---|---|
| 应用版本 | 仓库根 `version.json` → `version`（与 `pyproject.toml` 必须一致） | 每次发版递增 |
| 壳版本 | `desktop/src-tauri/Cargo.toml` → `version` | **独立于应用版本**，只有壳代码变更才递增 |
| 绑定副本 | `desktop/package.json` → `version`、`desktop/src-tauri/tauri.conf.json` → `version` | 必须与 Cargo.toml 逐字相等 |
| 最低壳版本 | `version.json` → `minimum_shell_version` | 应用更新包要求的最低壳版本；老壳拒绝装新包 |

`scripts/check_shell_version.py`（CI 门禁）校验上述四条，任何一处漂移即 CI 红。

> 历史教训：Image-DuoModel 曾出现 Cargo 1.0.0 / conf 1.0.2 不一致——壳自报 1.0.0，安装包写
> 1.0.2，`minimum_shell_version` 判定因此偏移一个版本。壳版本必须「一处定义、三处镜像」。

## 更新签名

本仓已生成一对**本仓专属**密钥（key id `4C937FD836C95882`，与其他三个仓互不复用）：

- 私钥 `desktop/tauri.key`：**绝不入库**（`.gitignore` 已挡）。**请立刻离线备份**（密码库 / 离线介质），
  丢失后所有存量用户只能靠重装新壳恢复更新能力。
- 公钥 `desktop/tauri.key.pub`：**必须入库**；`tauri.conf.json → plugins.updater.pubkey` 必须等于它的
  原文（一次 base64，首行 `untrusted comment: minisign public key: 4C937FD836C95882`）。
  二次 base64 会导致验签恒失败（家族仓 GOTCHAS #100 同型坑）。
- 这对密钥是**无密码**格式（`tauri signer generate` 不带 `-p` 时的产物）。签名时请显式给空密码：

  ```bash
  export TAURI_SIGNING_PRIVATE_KEY="$(cat desktop/tauri.key)"
  export TAURI_SIGNING_PRIVATE_KEY_PASSWORD=""      # 空串，不是"不设置"；不设置会转成交互式输入
  ```

- 若需换成带密码的密钥：`npx @tauri-apps/cli@2 signer generate -w desktop/tauri.key`（会覆盖），
  然后把新公钥同步进 `tauri.conf.json`，并递增壳版本（老壳无法验新签名，必须随新壳发布）。
- 更新端点：`https://github.com/ReSerendipity/VOSR2-Lite/releases/latest/download/shell-update.json`
  （壳自身更新）；应用增量包走 `app-v<ver>.zip` + `.sha256`（`updater.rs::ASSET_TEMPLATE`）。

## 壳不变量（改壳前必读）

跨四个仓（Image-DuoModel / TTS-MultiModel / SeedVR2-Lite / VOSR2-Lite）共用的硬约束，漂移即踩坑：

1. `build.rs::AppManifest::commands` 必须与 `main.rs::generate_handler!` **逐项一致**，且
   `permissions/autogenerated/<cmd>.toml` 全部入库——否则 `tauri-build` 报 `Permission not found`
   或运行期 IPC 被拒（GOTCHAS #104）。
2. `capabilities/main.json` 必须保留 `remote.urls` 的 `http://127.0.0.1:*`，否则导航到后端页面后
   所有 `invoke` 失效。
3. 壳只走两个后端契约：`GET /api/system/health`（就绪探测）与 `POST /api/system/shutdown`
   （优雅关闭）。关闭请求必须**自适应 CSRF**：先 GET 取 token（响应头 `X-CSRF-Token` 或
   `Set-Cookie: csrf_token=`），有则 double-submit，无则裸 POST。
4. `updater.rs::PRESERVE_TOP_DIRS` 必须覆盖本仓所有「大且用户私有」的目录。VOSR2 为
   `runtime / model / data / outputs / logs`（`outputs/` 是本仓特有，漏了会清空用户产物）。
5. 退出路径必须 `taskkill /T` 杀进程树 + `/api/system/shutdown` 优先，避免 torch/uvicorn 子进程
   持有 `app/` 句柄导致更新换载 `os error 32`。
6. 壳日志 `logs/vosr2lite-shell.log` 必须有滚动上限（当前 5 MB × 3 份）。

## 能力边界（VOSR2 首版）

`desktop/src/desktop-bridge.js` 提供：IPC、自绘标题栏（壳为无边框窗口）、更新弹窗与进度、
系统通知、任务态「按钮级」联动（`#btnStart` / `#btnCancel`）。

**未移植**（家族仓有、本仓暂缺，属有意收敛而非遗漏）：

- 拖拽文件注入（需按 VOSR2 的 `#dropzone` / `#fileInput` 结构重写；当前用浏览器原生拖放）
- SSE 任务终态解析（VOSR2 的 `/api/restore/{id}/progress` 是 EventSource 自动重连，没有
  明确的关闭信号，误判会让窗口长期显示「处理中」）
- `/api/system/settings` 目录授权（VOSR2 无此端点，桥接不得引用不存在的路由）
