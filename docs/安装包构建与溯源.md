# 安装包构建与溯源（TD-011）

> 2026-11-08 落地。对应 `docs/tech-debt.md` 的 TD-011：主分发物 `VOSR2Lite-Setup-v<版本>.exe`
> 原先「本地手工构建、产物不入库、无 SHA256、无 provenance、无代码签名」。
> 代码签名需要采购证书（属主裁决不做，见 TD-011 备注），因此本方案只补**可溯源**这一半，
> 并明确记录「未签名」这个事实，而不是让读者以为有签名。

## 一、发布物与校验物（强制，不再是「建议」）

| 文件 | 作用 |
| --- | --- |
| `VOSR2Lite-Setup-v<版本>.exe` | 主分发物（单文件安装包，数据卷已内嵌） |
| `SHA256SUMS.txt` | 安装包 + 构建输入的 SHA-256（`sha256sum -c` 可直接校验） |
| `VOSR2Lite-Setup-v<版本>.exe.provenance.json` | 该 exe 的来源：commit / tree / 是否脏树 / 工具版本 / 每个输入的哈希 / `signed: false` |

三者同目录、同一批次发布。**没有校验物或校验物与 exe 不符的安装包不得发布** ——
出包脚本在最后一步会自校验一次，不自洽直接失败退出。

## 二、构建（一条命令）

```powershell
pwsh -File scripts/installer/build_setup.ps1 `
  -DataVolume outputs/VOSR2Lite-Data.7z.001 `
  -ShellExe   scripts/installer/VOSR2Lite.exe
```

脚本做的事，顺序固定：

1. 版本一致性：`version.json` 的 `version` 必须等于 `setup.nsi` 的 `APP_VERSION`（改一处就是两个版本号）；
2. 输入存在性：数据卷、壳 exe、`7za.exe`（用于内嵌解压）缺一个就停；
3. 脏树检查：`git status --untracked-files=no` 有改动就拒绝出包（`-AllowDirty` 可强行，但 provenance 会标 `dirty: true`）；
4. `makensis` 编译；
5. 生成 `SHA256SUMS.txt` + `*.provenance.json`（`scripts/installer/provenance.py`）；
6. 立刻自校验：digest 与 provenance / 校验和不一致就失败。

## 三、用户侧校验

```powershell
# 校验和
Get-FileHash .\VOSR2Lite-Setup-v0.2.1.exe -Algorithm SHA256   # 与 SHA256SUMS.txt 比对
# 或直接跑工具（exe 与证据文件同目录）
python scripts/installer/provenance.py verify `
  --base-dir . `
  --provenance VOSR2Lite-Setup-v0.2.1.exe.provenance.json `
  --checksums SHA256SUMS.txt
```

`verify` 会做四件事：复算 exe 的 SHA-256 与大小、复算每个构建输入的哈希、检查
`source.commit` 是否存在、检查 `source.dirty` 是否为 false。任一条不符退出码为 1。

## 四、「可复现」这件事的实测口径

不能只写在文档里说「可复现」，2026-11-08 在本机用 NSIS 3.10 做了对照实验：

- 同一份 `.nsi`（含一个 4 KB 内嵌文件负载），**都不设** `SOURCE_DATE_EPOCH`，
  两次构建间隔 3 秒 → 两次产物 SHA-256 相同（`8923FAF6…F8433BA`）；
- 第三次设置 `SOURCE_DATE_EPOCH=1793491200` → 同一哈希；
- 直接读 PE 头：两种情况下 `TimeDateStamp` 都是 `1711817723`（2024-03-30），
  即 makensis stub 自带的常量，**不随挂钟变化**。

结论：NSIS 3.10 对「同一脚本 + 同一输入」本身就是逐字节确定的，所以「同一 commit 重建出
同一 digest」成立，校验和才有意义。脚本仍设 `SOURCE_DATE_EPOCH`（= HEAD 提交时间），
那是给将来换 NSIS 版本或换工具时留的退路，**不是复现的前提** —— 别把它当成功臣。

## 五、仍未做（如实记录）

- **代码签名**：需要 OV/EV 代码签名证书（采购属外部依赖），本方案不覆盖。用户首次运行仍会看到
  SmartScreen 提示，这是无签名的必然结果，不是构建问题。
- **CI 构建**：数据卷是本地组装产物（`.gitignore` 排除，100 MB 级），CI 拿不到，所以现在做不到
  「CI 出安装包」。当前口径是「本地构建 + 强制附校验物」，CI 侧 `release.yml` 仍只发源码 zip + SBOM + SLSA。
  若将来把数据卷做成可下载的构建输入，可把本脚本搬进 Windows runner 并把 provenance 交给
  `actions/attest-build-provenance`。
- **真机安装复验**：本机缺少数据卷（`VOSR2Lite-Data.7z.001`），无法在这里完整重打一次 100 MB
  安装包，因此「装完能启动」这一步未在本轮验证；工具本身已在**真实 103 MB 产物**上跑通
  （`write` 得到 `49593c2c…2f27e8`，`verify` 正确报出 `source.dirty=true`）。
