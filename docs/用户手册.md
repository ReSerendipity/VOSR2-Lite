# VOSR2-Lite 用户手册

> 面向**实际使用者**：参数怎么选、按钮怎么用、出问题怎么查。
> 想先跑起来请看 [README 快速开始](../README.md#快速开始)（约 10 分钟）；
> 想改代码请看 [AGENTS.md](../AGENTS.md) 与 [docs/agent-contract.md](agent-contract.md)。

---

## 1. 它解决什么问题

把低分辨率图片放大并**重建细节**（不是简单插值）：老照片、截图、压缩过度的
素材、需要放大的商品图。核心是 VOSR2 扩散模型——按目标尺寸重新生成细节，
所以细节是"重建"出来的，不是"拉伸"出来的。

**不适合**：需要严格保真的证据图（生成模型会重写小字与纹理）；纯 CPU 环境
（必须 NVIDIA GPU）；视频（本仓只做图像，视频请用 SeedVR2-Lite）。

## 2. 界面地图

| 页面 | 用途 |
|---|---|
| 首页 | 能力概览与入口 |

## 3. 上传图片

三种方式，效果相同：

1. 点虚线区域选择文件（支持一次多选，按队列串行处理）；
2. 把文件从资源管理器直接拖进虚线区域；
3. **Ctrl+V 粘贴**——从截图工具或网页复制图片后，在工作台按 Ctrl+V 即入队。

支持格式：PNG / JPEG / GIF / BMP / WebP / TIFF。服务端会校验文件头魔数，
扩展名与内容不符会被拒绝（提示"疑似伪造格式"）。

## 4. 参数怎么选

### 4.1 放大倍率（×1 / ×2 / ×3 / ×4）

输出尺寸 = 输入尺寸 × 倍率。**倍率只影响目标尺寸**，不改变模型细节强度。

- 只想修细节、不改尺寸 → ×1（模型仍会重建，只是不放大）；
- 常用 → ×2 / ×4；
- 输出长边上限 6144 px：超限会直接被拒，并提示"本图最高 ×N"。

### 4.2 采样步数（1 / 25）

| 步数 | 适用检查点 | 特点 |
|---|---|---|
| 1 | `VOSR2` / `VOSR_1.4B_os` / `VOSR_0.5B_os` | 一步蒸馏，最快，日常首选 |
| 25 | `VOSR_1.4B_ms` | 多步 + CFG，忠实度更高，慢约 20 倍 |

多步模型（`*_ms`）有硬门槛：**输出长边必须 ≥384 px**（训练分辨率 512；实测
≤256 px 轨迹发散、糊成色块）。低于门槛会被前置拒绝并提示改倍率或改一步。

### 4.3 颜色对齐（wavelet / adain / nofix）

生成模型容易让整体色调漂移，这一步把颜色拉回原图：

- **wavelet（默认）**：低频取原图、高频保留模型细节——既不偏色又不糊细节，
  绝大多数情况用这个；
- **adain**：把结果的均值/方差对齐到原图。色调更"贴"，但会连带压掉一点
  生成细节；适合原图色偏明显的场景；
- **nofix**：不做任何处理。只有在你明确想保留模型原始色调时才用。

### 4.4 分块（默认「自动」，建议保持）

Qwen VAE 是 fp32，全图编码约 11 KB/像素——3096² 输出光编码就要 ~100 GB 显存。
所以引擎按「输出尺寸 + 可用显存」自动开两级分块：

| 输出长边 | 可用显存 | DiT 分块 | VAE 分块 |
|---|---|---|---|
| ≤512 | 任意 | 关 | 关 |
| 513–1024 | 任意 | 512 | 关 |
| >1024 | ≤16 GB | 512 | 512 |
| >1024 | >16 GB | 512 | 1024 |

手动填值（>0）会覆盖自动决策；填 0 表示"交回自动"。只有在自动策略导致 OOM
或明显变慢时才建议手动干预（例如显存被其他程序占用时把 VAE 分块降到 512）。

### 4.5 随机种子（默认 42）

扩散采样带随机性。固定种子 + 相同参数 = 可复现的同一张输出（便于对比不同
参数的效果）；填 `-1` 表示每次随机。

## 5. 对比查看器

结果出来后进入前后对比视图，操作方式：

| 操作 | 效果 |
|---|---|
| 拖动中间分割线 | 左原图 / 右结果，同一位置对照 |
| 滚轮 | 以光标位置为中心缩放 |
| 拖拽画面 | 平移 |
| 「1:1」按钮 | 切到原生像素（判断细节是真恢复还是被插值糊住） |
| 「适配」按钮 | 整图缩放到窗口内 |

右上角有缩放百分比 HUD。放大到 1:1 时以画面中心为锚点，先看中心而不是左上角。

## 6. 下载与格式转换

结果页与历史记录都能下载，支持即时转换：

- **PNG**（默认，无损）
- **JPEG**（可调质量，体积小）
- **WebP**（体积最小，现代浏览器通用）

转换在服务端完成，不落中间文件（除缩略图缓存）。原图、预览、下载三个端点都
走路径白名单校验，只允许读 `outputs/` 与 `data/uploads/` 下的文件。

## 7. 历史记录与数据落盘

| 路径 | 内容 | 能否删 |
|---|---|---|
| `data/uploads/` | 每次上传的原图（文件名带 task_id 前缀） | 可删，历史里将无法再对比原图 |
| `outputs/` | 修复结果 PNG | 可删，历史里"下载"会失效 |
| `data/history.db` | 任务与记录（SQLite） | **删了就丢历史**；建议先备份 |
| `data/cache/thumbs/` | 缩略图缓存 | 可随时删，自动重建 |
| `data/.vosr2_secret` | CSRF 签名密钥（首次启用 CSRF 时生成） | 可删，会重新生成（已签发的 token 失效） |
| `model/` | 模型权重 | 可删，用下载脚本重取 |

历史记录支持分页（每页 20 条，最大 100）与按状态筛选；删除记录只删数据库
行，不删磁盘上的图片文件（需要腾空间请自行清理 `outputs/`）。

## 8. 安全开关（默认全关）

服务默认只绑 `127.0.0.1`，本机自用无需任何认证。**一旦要绑到局域网 / 公网 /
容器端口映射，必须先开启 Basic Auth**——否则等于把 GPU 推理与上传接口完全开放。

```yaml
# config.yaml
runtime:
  security:
    auth:
      enable: true
      username: admin
      password: ""          # 建议留空，用环境变量注入
      realm: VOSR2
      max_auth_failures: 5      # 窗口内失败次数上限（<=0 关闭防爆破）
      auth_failure_window_seconds: 300
      auth_ban_seconds: 600
    csrf:
      enable: false         # 对外暴露时建议开启
```

推荐用环境变量注入密码（避免明文入库）：

```bash
set VOSR2_AUTH_USERNAME=admin
set VOSR2_AUTH_PASSWORD=换成强密码
```

同时注入这两个变量即视为启用，无需改 `config.yaml`（容器部署快捷通道）。

**行为**：未带凭据 → 401 + `WWW-Authenticate`（浏览器自动弹框）；窗口内失败
达上限 → 429 + `Retry-After`，封禁期内即使凭据正确也拒绝。

**CSRF**（`csrf.enable: true`）：前端 `app.js` 已自动回传 `X-CSRF-Token`，开启后
无需改前端。语言切换接口豁免（只改显示偏好）。

> ⚠️ Basic Auth 的凭据是 Base64 明文传输，公网部署必须叠加 HTTPS 反向代理。

## 9. 配置文件速查

```yaml
server:
  host: 127.0.0.1      # 改成 0.0.0.0 前务必先开 Basic Auth
  port: 7871           # 被占用会自动顺延
model:
  pretrained_dir: model
  default_checkpoint: VOSR2
  idle_unload_minutes: 15   # 空闲多久卸载引擎（释放显存）
inference:
  max_output_side: 6144     # 输出长边硬上限
  align_methods: [wavelet, adain, nofix]
runtime:
  task:
    queue_maxsize: 100      # 队列满时上传返回 503
    max_timeout_seconds: 86400
  sse:
    heartbeat_interval_seconds: 30
```

环境变量覆盖：`VOSR2_ALLOWED_ORIGINS`（CORS 白名单，逗号分隔）、
`VOSR2_ENABLE_DOCS=0`（关闭 /docs）、`VOSR2_SECRET_KEY`（CSRF 密钥）、
`LOG_LEVEL`、`LOG_PATH`。

## 11. 故障排查

| 症状 | 原因 | 处置 |
|---|---|---|
| 启动即报"未找到权重" | `model/` 下缺文件或目录层级不对 | `python scripts/download_model.py`；确认 `model/VOSR2/args.json` 存在 |
| `torch.cuda.is_available()` 为 False | 装成了 CPU 版 torch（常见于 pip 配了镜像 extra-index） | `set PIP_CONFIG_FILE=NUL` 后按 README 用 cu128 索引重装 |
| 任务失败且日志出现 `CUDA out of memory` | 分块被关掉，或显存被其他程序占用 | 分块恢复「自动」；关闭其他占显存程序；换 `VOSR_0.5B_os` |
| 多步模型输出糊成色块 | 输出长边 <384 px | 提高倍率或换更大输入；引擎已前置拒绝该情况 |
| 图里小字被"重写"成错字 | 生成模型的固有行为（按语义重绘） | 换 `VOSR_1.4B_ms` 多步模型；或裁出文字区域单独处理 |
| 上传被拒"疑似伪造格式" | 扩展名与实际内容不符 | 用图片工具重新导出，不要直接改后缀 |
| 输出过大被拒 | 超过 6144 px | 按提示降倍率或先裁剪 |
| 进度条卡住不动 | 推理在跑但没新阶段（大图分块耗时长） | 看「系统状态」显存占用；超过 `progress_stall_timeout_minutes` 会判失败 |
| 页面样式错乱 | 静态资源缓存了旧版本 | 强制刷新（Ctrl+F5） |

日志位置：`logs/app.log`（按 50 MB 轮转，保留 3 份）。排查推理问题优先看
`logs/app.log` 里 `[分块推理]` 与 `引擎就绪` 两行，能确认分块策略与显存占用。

## 12. 数据与隐私

全部处理在本机完成，不上传任何图片到外部服务。模型下载走 HuggingFace 镜像
（`hf-mirror.com`）或 ModelScope，只下载权重。历史库是本地 SQLite，删除记录
即从库中移除。
